需要现场展示成功退款时，可以在 SSMS 单独执行以下事务，最后回滚以保持演示基准：

```sql
USE OnlineEducationSQL;
DECLARE @s int=(SELECT student_id FROM dbo.student WHERE email=N'li.demo@example.test');
DECLARE @o bigint=(SELECT MIN(order_id) FROM dbo.order_info WHERE student_id=@s AND status='PAID');
BEGIN TRAN;
EXEC dbo.usp_RefundOrder @s,@o,N'现场展示：进度等于20%';
SELECT * FROM dbo.order_info WHERE order_id=@o;
SELECT * FROM dbo.refund_record WHERE order_id=@o;
ROLLBACK;
```

SSMS 操作不需要 Java 或浏览器。演示使用数据库模拟订单支付和退款，不执行现实资金交易。

## 模块化验收方式

本次整理后实际完成以下验证：现有数据库升级课程名称并运行生成入口；随机命名的临时空库按 01～08 源模块从零安装；逐个运行全部测试文件和 91_demo；重复执行安装和统一验收。两种安装路径均通过 21 组检查，临时验证库已删除。另在临时脚本中注入预期错误 52997，确认即使 sqlcmd 未使用 -b，也不会输出 ALL TESTS PASSED。此项只验证验收入口的错误处理，不修改业务数据。

先完整安装，再执行 tests 下某个成员的测试文件，可只检查该成员负责的场景。各文件都使用演示基准数据，不是彼此完全隔离的空库单元测试。

92_acceptance.sql 按顺序运行所有模块测试及 09_integration_tests.sql，使用一个外层 TRY/CATCH 包装各批次的执行。任意批次抛出错误时，不会继续输出 ALL TESTS PASSED；这避免 SSMS 在 GO 后继续执行导致误报全部通过。单独测试文件没有总体成功标记，应检查其所有消息。

入口由 database/tools/build-bundles.ps1 生成，-Check 可验证源文件与入口同步。工具只处理本地文本，不连接数据库。
